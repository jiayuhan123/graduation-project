# 小学数学个性化练习与游戏闯关平台

本项目是一套面向小学生、教师和管理员的小学数学基础计算学习平台。当前版本聚焦人教版小学数学计算类知识点，使用数据库中已经审核启用的固定题目完成自主练习、教师作业和学习诊断闭环。

> 第一版坚持“小范围做深”：先完成可运行、可解释、可验证的学习闭环。开发者开放平台暂停；一对一 PK 仅作为后续可选扩展。

## 核心学习闭环

```text
自主练习、教师作业或游戏闯关
    → 可信批改
    → 定位错题和具体错因
    → 更新知识点掌握情况
    → 安排针对性练习
    → 再次验证
```

所有场景产生的作答记录都进入学生学习档案。系统不会因为一次答对就直接认定学生已经掌握，而是结合正确率、答题速度、题目难度、练习频率和最近练习时间持续更新掌握情况。

## 第一版业务角色

### 学生

- 选择年级、学期和计算类知识点，完成固定题库自主练习、教师作业和游戏闯关。
- 查看错题、错因、掌握情况、推荐练习、积分、经验、关卡和团队成绩。
- 可以独立使用核心学习功能；加入班级后可接收教师作业和训练任务。

### 教师

- 管理本人负责的班级和学生，布置统一或分层作业。
- 查看完成情况、错题分布和薄弱知识点。
- 只能查看本人班级学生的学习报告，并根据学情发布后续训练。

### 管理员

- 维护内容模块、知识点、题目、答案、难度、错因分类和业务规则。
- 配置练习、批改、推荐、关卡、积分、经验和团队闯关规则。
- 处理低可信批改、异常作答和内容质量问题。

整体概念 ER 图直接使用学生、教师和管理员三类业务实体表达参与关系；实际系统仍使用统一账号、角色、权限和用户角色关联实现 RBAC 鉴权。

## 三项核心业务

### 1. 拍照批改（暂未开放）

- 本轮不开发拍照上传、OCR 识别或人工复核命令流程。
- 前端只展示“暂未开放”说明，并保留对数据库既有拍照批改任务的本人查询入口。

### 2. 个性化口算练习

- 根据学生年级、所选知识点、近期错题和掌握情况，从数据库中已经审核启用的固定题目选择下一组练习，不调用大模型生成题目。
- 已经稳定掌握的内容减少重复；薄弱内容增加练习；长期未练的内容安排适量复习。
- 支持普通练习和限时练习；自主练习逐题立即判题，答错后可以重新尝试。
- 教师作业答题过程中只保存答案，整份作业最终提交后统一反馈，提交后不能修改。
- 推荐练习完成后再次更新掌握情况，形成“发现问题—针对训练—再次验证”的闭环。

### 3. 个人/团队游戏闯关

闯关不是给普通答题页面增加积分，而是让答题直接推动游戏过程。

#### 单人闯关

- 学生主动选择年级和知识点发起挑战，系统结合当前掌握情况生成题目。
- 第一版默认每关 10 题，设置总答题时限；在规定时间内完成且正确率达到 80% 时闯关成功。题量、时限和通过率均为关卡属性，可配置。
- 答对后角色推进，连续答对形成连击并获得额外能量；答错后角色暂时停止，展示简短错因提示。
- 成功后获得积分、经验和关卡解锁；失败也保留记录，并先生成巩固练习，完成后可以再次挑战。

#### 团队闯关

- 支持 2 至 4 名学生组成队伍完成共同关卡，成员使用相同知识点和相近难度的等价题目。
- 每名成员独立作答，正确结果共同推动队伍进度；结算时保留团队结果、个人正确题数、得分和贡献情况。
- 团队闯关产生的错题同样进入个人学习档案，不因游戏场景而脱离诊断和推荐流程。

一对一实时 PK 不作为第一版完成条件，后续可在闯关与作答数据稳定后扩展。

## 内容组织方式

第一版不围绕大量教材版本建立复杂模型，按“内容模块—知识点—题目”组织核心内容：

```text
内容模块 1:N 知识点
知识点 M:N 题目
```

- 内容模块按照年级、学期和主题划分，例如“二年级上册·100 以内加减法”。
- 当前只维护人教版小学数学，不处理多教材版本选择和映射。
- 题库仅收录计算相关知识点，不处理图形学习等非计算内容。

## 第一版配套业务

- 题库与规则：维护固定题目、标准答案、难度、计算类知识点和适用范围。
- 教师作业：支持选题、规则组题、统一作业、分层作业和完成统计。
- 学习档案：汇总练习、批改、错题、掌握情况、推荐和闯关记录。
- 学习报告：提供学生和班级两个视角的正确率、错因分布、薄弱知识点和阶段趋势。
- 运营管理：维护内容与规则，处理低可信批改和异常记录。

## 第一版业务边界

- 聚焦小学数学基础计算，不扩展为全学科教务平台。
- 家长不作为第一版独立角色。
- 开发者开放平台暂停，不建设应用密钥、调用额度和开放接口运营体系。
- 一对一 PK 为后续可选扩展，不单独拆分服务。
- 学校和班级不是学生使用核心学习功能的前置条件。
- 练习组题不调用大模型，只使用数据库已有固定题目。
- 拍照 OCR 本轮不开发，只保留未开放说明和已有数据查询入口。
- 教师只能查看本人班级学生学情；管理员可以查看全部学生学情。

## 第一版完成标准

- 学生能够完成个性化口算“生成—作答—诊断—推荐—再次验证”的闭环。
- Web 和小程序明确展示拍照 OCR 暂未开放，不伪造识别或批改结果。
- 单人闯关具备题目生成、限时答题、游戏推进、结算、奖励、失败巩固和再次挑战。
- 团队闯关能够形成团队进度、个人贡献和个人学习记录。
- 教师能够布置作业，并查看本人班级学生学情；管理员能够查看全部学生学情。
- 整体 ER 图只展示核心实体和关系；题量、时限、通过率、教材版本、角色等作为属性表达。

## 当前工程

### 后端

- Java 21 / Spring Boot 4 多模块微服务工程。
- 已有 Gateway、用户、内容题库、学习闭环、教学、游戏、文件、通知、审计服务及公共能力模块。
- 内容服务已具备管理端 CRUD、题目审核、学习端内容目录、跨服务权限校验和事务发件箱审计；学习服务已接通自主练习、教师作业、即时/最终判题、错题、掌握度、推荐、学习报告和可靠作业进度回写；教学服务已接通班级与作业流程。

### 前端

- Vue 3 + TDesign Vue Next Web 端已提供学生练习与档案、教师本人班级学情、管理员全量学情入口。
- 原生微信小程序已接入自主练习、错题、掌握度、推荐、拍照历史查询，以及从教师作业直接进入答题的流程。
