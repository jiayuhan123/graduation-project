### 1.3 PostgreSQL 与 Navicat 类型对照

| 标准写法 | Navicat 类型 | 长度 | 小数点 | 用途 |
| --- | --- | :---: | :---: | :---: |
| `BIGINT` | `int8` | 留空 | 留空 | Java `Long`、雪花 ID |
| `INTEGER` | `int4` | 留空 | 留空 | 普通整数、计数、版本号 |
| `SMALLINT` | `int2` | 留空 | 留空 | 年级、学期、状态等小整数 |
| `BOOLEAN` | `bool` | 留空 | 留空 | 是/否 |
| `VARCHAR(n)` | `varchar` | 填 `n` | 留空 | 有最大长度的文本 |
| `CHAR(64)` | `char` | `64` | 留空 | 固定 64 位 SHA-256 |
| `TEXT` | `text` | 留空 | 留空 | 题干、解析、长文本 |
| `UUID` | `uuid` | 留空 | 留空 | 文件、事件、通知等随机 ID |
| `TIMESTAMPTZ` | `timestamptz` | 留空 | 留空 | 带时区时间，与 Java OffsetDateTime / Instant 对应 |
| `JSONB` | `jsonb` | 留空 | 留空 | 答案、规则、快照等结构化数据 |
| `NUMERIC(5,4)` | `numeric` | `5` | `4` | 0.0000～1.0000 的比率/可信度 |
| `NUMERIC(8,2)` | `numeric` | `8` | `2` | 分数、贡献值等两位小数 |

“长度”是总有效数字位数，“小数点”是小数位数。例如 `NUMERIC(5,4)` 最多有 5 位有效数字，其中 4 位在小数点后，可保存 `0.8000`、`1.0000`。`int8`、`varchar` 等类型的小数点必须留空。

### 1.4 全局约定

本设计参考《阿里巴巴 Java 开发手册》，并结合 PostgreSQL 原生类型和微服务数据边界进行适配；不机械照搬 MySQL 专属类型。

表名和字段名统一使用小写蛇形命名；表示是/否的数据库字段统一使用 `is_xxx`，PostgreSQL 类型使用原生 `BOOLEAN`。

1. 业务主表的 `BIGINT` 主键默认由后端雪花算法生成，因此 Navicat 中只设“主键、非空”，不要勾选自动递增。
2. `sys_role.id`、`sys_permission.id` 使用 PostgreSQL Identity，自增设置为“按默认生成”。
3. 多对多关联表使用联合主键，不再额外增加无意义的 `id`。
4. 所有关联只保存业务 ID，不建立 PostgreSQL 物理外键，也不使用级联删除；数据一致性由应用事务、领域事件和幂等补偿保证。
5. 枚举状态使用 `VARCHAR` 或 `SMALLINT` 加 `CHECK`，不使用 PostgreSQL 自定义枚举，便于以后迁移。
6. `created_at`、`updated_at` 对应阿里规约中的 `gmt_create`、`gmt_modified`；统一使用 `TIMESTAMPTZ` 并按 UTC 保存，`updated_at` 由后端更新，不依赖数据库触发器。
7. 可修改主表一般包含 version 乐观锁；需要恢复或避开唯一键冲突的资料表使用 `is_deleted` 逻辑删除。
8. 密码只存 BCrypt 哈希；题目、答案、审计中不得保存明文密码、Token 或 AccessKey。
9. SQL 中约束名前缀：`pk_` 主键、`uk_` 唯一约束/索引、`ck_` 检查约束、`idx_` 普通索引；不定义 `fk_` 物理外键。

### 1.5 跨服务核心数据流

```text
user_db：学生/教师账号
    ├─ content_db：管理员维护模块、知识点、题目和错因字典
    ├─ teaching_db：教师组织班级并发布作业
    ├─ learning_db：所有入口的题目最终形成统一答题记录
    │      ├─ 拍照批改 → 答题记录 → 错因 → 掌握度 → 推荐练习
    │      └─ 教师作业/游戏对局 → 练习任务 → 答题记录 → 同一学习闭环
    ├─ game_db：保存游戏规则、对局过程、个人贡献和奖励
    ├─ file_db：保存拍照图片等文件的元数据
    ├─ notification_db：保存发给用户的站内通知
    └─ audit_db：保存关键操作审计日志
```

### 2.2 `t_user`——统一账号表

用途：只保存所有登录主体共用的账号、凭证、安全状态和基础资料。学生、教师、管理员身份由 RBAC 角色决定。

| 字段 | PostgreSQL 类型 | Navicat 类型 | 长度/小数 | 非空 | 默认值 | 键/规则 | 注释 |
| --- | --- | --- | :---: | :---: | :---: | --- | --- |
| `id` | `BIGINT` | `int8` | — | 是 | — | PK，不自增 | 用户编号，后端雪花 ID |
| `username` | `VARCHAR(32)` | `varchar` | 32 | 是 | — | 有效账号忽略大小写唯一 | 登录用户名 |
| `wechat_openid` | `VARCHAR(64)` | `varchar` | 64 | 否 | — | 有效非空值唯一 | 微信小程序 OpenID，用于登录与账号绑定 |
| `password` | `VARCHAR(100)` | `varchar` | 100 | 否 | — | — | BCrypt 密码哈希，不能存明文 |
| `nickname` | `VARCHAR(50)` | `varchar` | 50 | 否 | — | — | 昵称 |
| `real_name` | `VARCHAR(50)` | `varchar` | 50 | 否 | — | — | 真实姓名 |
| `email` | `VARCHAR(254)` | `varchar` | 254 | 否 | — | 有效非空邮箱忽略大小写唯一 | 邮箱 |
| `phone` | `VARCHAR(20)` | `varchar` | 20 | 否 | — | 有效非空手机号唯一 | 手机号 |
| `avatar` | `VARCHAR(500)` | `varchar` | 500 | 否 | — | — | 头像地址或文件访问标识 |
| `status` | `SMALLINT` | `int2` | — | 是 | `1` | 0 禁用，1 正常 | 账号状态 |
| `last_login_at` | `TIMESTAMPTZ` | `timestamptz` | — | 否 | — | — | 最近登录成功时间 |
| `last_login_ip` | `VARCHAR(64)` | `varchar` | 64 | 否 | — | — | 最近登录 IP |
| `password_changed_at` | `TIMESTAMPTZ` | `timestamptz` | — | 否 | — | — | 最近密码设置时间 |
| `created_at` | `TIMESTAMPTZ` | `timestamptz` | — | 是 | `CURRENT_TIMESTAMP` | — | 创建时间 |
| `updated_at` | `TIMESTAMPTZ` | `timestamptz` | — | 是 | `CURRENT_TIMESTAMP` | — | 更新时间 |
| `is_deleted` | `BOOLEAN` | `bool` | — | 是 | `FALSE` | 逻辑删除 | 是否已删除 |
| `version` | `INTEGER` | `int4` | — | 是 | `0` | ≥ 0 | 乐观锁版本号 |

#### 建表 SQL

```sql
CREATE TABLE t_user (
id                  BIGINT CONSTRAINT pk_t_user PRIMARY KEY,
username            VARCHAR(32)  NOT NULL,
wechat_openid                 VARCHAR(64),
password            VARCHAR(100) NOT NULL,
nickname            VARCHAR(50),
real_name           VARCHAR(50),
email               VARCHAR(254),
phone               VARCHAR(20),
avatar              VARCHAR(500),
status              SMALLINT     NOT NULL DEFAULT 1,
last_login_at       TIMESTAMPTZ,
last_login_ip       VARCHAR(64),
password_changed_at TIMESTAMPTZ,
created_at          TIMESTAMPTZ    NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_at          TIMESTAMPTZ    NOT NULL DEFAULT CURRENT_TIMESTAMP,
is_deleted             BOOLEAN      NOT NULL DEFAULT FALSE,
version             INTEGER      NOT NULL DEFAULT 0,
CONSTRAINT ck_t_user_status CHECK (status IN (0, 1)),
CONSTRAINT ck_t_user_version CHECK (version >= 0)
);
CREATE UNIQUE INDEX uk_t_user_username_active
ON t_user (LOWER(username)) WHERE is_deleted = FALSE;
CREATE UNIQUE INDEX uk_t_user_phone_active
ON t_user (phone) WHERE is_deleted = FALSE AND phone IS NOT NULL;
CREATE UNIQUE INDEX uk_t_user_email_active
ON t_user (LOWER(email)) WHERE is_deleted = FALSE AND email IS NOT NULL;
CREATE INDEX idx_t_user_status_created_at
ON t_user (status, created_at DESC) WHERE is_deleted = FALSE;
CREATE UNIQUE INDEX uk_t_user_wechat_openid
ON t_user (wechat_openid)
WHERE wechat_openid IS NOT NULL AND is_deleted = FALSE;
COMMENT ON TABLE t_user IS '统一账号表';
COMMENT ON COLUMN t_user.id IS '用户编号，后端雪花 ID';
COMMENT ON COLUMN t_user.username IS '登录用户名';
COMMENT ON COLUMN t_user.wechat_openid IS '微信小程序 OpenID，用于登录与账号绑定';
COMMENT ON COLUMN t_user.password IS 'BCrypt 密码哈希，不能存明文';
COMMENT ON COLUMN t_user.nickname IS '昵称';
COMMENT ON COLUMN t_user.real_name IS '真实姓名';
COMMENT ON COLUMN t_user.email IS '邮箱';
COMMENT ON COLUMN t_user.phone IS '手机号';
COMMENT ON COLUMN t_user.avatar IS '头像地址或文件访问标识';
COMMENT ON COLUMN t_user.status IS '账号状态';
COMMENT ON COLUMN t_user.last_login_at IS '最近登录成功时间';
COMMENT ON COLUMN t_user.last_login_ip IS '最近登录 IP';
COMMENT ON COLUMN t_user.password_changed_at IS '最近密码设置时间';
COMMENT ON COLUMN t_user.created_at IS '创建时间';
COMMENT ON COLUMN t_user.updated_at IS '更新时间';
COMMENT ON COLUMN t_user.is_deleted IS '是否已删除';
COMMENT ON COLUMN t_user.version IS '乐观锁版本号';
```

主要索引：`uk_t_user_username_active`、`uk_t_user_phone_active`、`uk_t_user_email_active`、`idx_t_user_status_created_at`。

关系：与学生资料、教师资料均为 `1 : 0..1`；通过 `sys_user_role` 与角色形成 `M : N`。

## 12. Navicat 手工建表步骤

每张表按以下顺序操作，便于发现错误：

1. 连接对应数据库，展开“模式 → public → 表”，选择“新建表”。
2. 按数据字典逐行填写字段名、类型、长度、小数点、非空和默认值。
3. 设置主键：单主键直接点工具栏“主键”；联合主键同时选中两列后设置。
4. `BIGINT` 雪花主键不要启用自动递增；只有 `sys_role.id`、`sys_permission.id` 设置 Identity。
5. 不要在 Navicat 的“外键”页添加任何物理外键；所有关联 ID 按本文索引设计创建索引，并由应用层校验。
6. 在“检查”页添加 `ck_...` 约束；在“索引”页添加普通、唯一和部分索引。
7. 保存表后，用“SQL 预览”与本文完整 SQL 对照，特别核对默认值是否被 Navicat 自动加了错误引号。
8. 每完成一个数据库，运行第 13 节的检查 SQL，确认表数、主键、`CHECK` 和索引，并确认物理外键数量为 0。

默认值填写提示：

| 目标默认值 | Navicat 默认值栏 |
| --- | --- |
| 当前时间 | `CURRENT_TIMESTAMP`，不要加单引号 |
| 布尔假 | `false`，不要写成字符串 `'false'` |
| 数字 0/1 | `0` 或 `1`，不要加单引号 |
| 字符串状态 | `'PENDING'`、`'ACTIVE'`，需要单引号 |

```sql
ORDER BY ordinal_position;
```

### 13.3 检查主键、唯一和 `CHECK`（物理外键应为 0）

```sql
SELECT
    conrelid::regclass AS table_name,
    conname           AS constraint_name,
    CASE contype
        WHEN 'p' THEN 'PRIMARY KEY'
        WHEN 'u' THEN 'UNIQUE'
WHEN 'f' THEN 'FOREIGN KEY（目标结构应为 0）'
        WHEN 'c' THEN 'CHECK'
        ELSE contype::text
    END AS constraint_type,
    pg_get_constraintdef(oid) AS definition
FROM pg_constraint
WHERE connamespace = 'public'::regnamespace
ORDER BY conrelid::regclass::text, conname;
```

### 13.4 检查索引

```sql
SELECT tablename, indexname, indexdef
FROM pg_indexes
WHERE schemaname = 'public'
ORDER BY tablename, indexname;
```

### 13.5 检查所有 `BIGINT` 主键是否误设自增

除 `sys_role.id`、`sys_permission.id` 外，雪花 ID 的 `column_default` 应为空。

```sql
SELECT table_name, column_name, column_default, is_identity
FROM information_schema.columns
WHERE table_schema = 'public'
  AND column_name = 'id'
ORDER BY table_name;
```

## 14. 手工建表与结构维护

1. 本文档描述的是当前目标模型，也是项目未启用自动数据库迁移期间的建表依据。
2. 首次启动微服务前，应先创建对应数据库，并按本文档顺序执行建表、索引和初始化数据 SQL。
3. 修改表结构时，应同步修改本文档并记录变更内容，确保本地、测试和部署环境保持一致。
4. 如果某数据库只是学习用，推荐命名为 `user_db_lab` 等，避免与服务实际数据库混淆。
5. 正式库修改前必须先备份并在测试库验证 SQL，不要直接执行未经验证的结构变更。

## 15. 建表学习顺序建议

不要一次把 40 张表全部点完。按下面顺序学习，能逐步理解关系：

1. `user_db`：先理解主键、唯一索引、1:1、M:N 和 RBAC。
2. `content_db`：理解 1:N、自关联、M:N、`JSONB` 和 `NUMERIC(5,4)`。
3. `learning_db`：理解任务—题目—作答—错因—掌握度的核心闭环。
4. `teaching_db`：理解班级关系、分层作业和跨服务逻辑引用。
5. `game_db`：理解单人/团队共用模型、过程记录、进度快照和奖励流水。
6. 文件、通知、审计三个小库最后创建，用来复习 `UUID`、幂等唯一键、部分索引和不可变日志。

完成一张表后，建议同时回答三个问题：这张表保存的唯一事实是什么；哪些字段必须由数据库保证；它与其他表之间的逻辑关系由哪个业务 ID 和索引支撑。能说清楚这三个问题，就不只是“照着建表”，而是真正理解了设计。
