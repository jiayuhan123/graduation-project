## 1. 整体安全架构

本项目安全体系分为三个层次：

```
┌──────────────────────────────────────────────────────┐
│                   网络层安全                           │
│  • 防火墙：仅开放必要端口                              │
│  • Docker 网络：中间件不对外暴露                       │
│  • HTTPS：传输加密（生产环境）                         │
└──────────────────────────────────────────────────────┘
                         │
┌──────────────────────────────────────────────────────┐
│                 网关层鉴权（Core）                     │
│  • Sa-Token 验证 Token 有效性                         │
│  • Redis 查询 Token-UserId 映射                       │
│  • 白名单接口放行                                      │
│  • 注入 X-User-ID 请求头                              │
└──────────────────────────────────────────────────────┘
                         │
┌──────────────────────────────────────────────────────┐
│               业务服务层权限控制                        │
│  • 读取 X-User-ID 识别用户身份                        │
│  • 资源所有权验证（只能操作自己的数据）                 │
│  • 管理员权限注解（@SaCheckRole）                      │
└──────────────────────────────────────────────────────┘
```

## 2. Sa-Token 集成方案

### 2.1 依赖配置

**网关服务**（WebFlux 响应式环境）：
```xml
<!-- Sa-Token 响应式版本，适配 WebFlux -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-reactor-spring-boot3-starter</artifactId>
    <version>${sa-token.version}</version>
</dependency>
<!-- Sa-Token Redis 集成 -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-redis-jackson</artifactId>
    <version>${sa-token.version}</version>
</dependency>
```

**用户服务**（Servlet 环境）：
```xml
<!-- Sa-Token Spring Boot 3 版本 -->
<dependency>
    <groupId>cn.dev33</groupId>
    <artifactId>sa-token-spring-boot3-starter</artifactId>
    <version>${sa-token.version}</version>
</dependency>
```

### 2.2 Sa-Token 核心配置

```yaml
# Nacos 中 user-service.yaml 的 Sa-Token 配置
sa-token:
  # Token 名称（请求头字段名）
  token-name: satoken
  # Token 有效期：7 天（单位：秒）
  timeout: 604800
  # Token 临时有效期（活跃超时）：24 小时
  active-timeout: 86400
  # 是否允许同一账号多地同时登录
  is-concurrent: true
  # 是否共用同一个 Token（true=同设备类型共用）
  is-share: false
  # Token 风格：UUID 随机字符串
  token-style: uuid
  # 是否输出操作日志
  is-log: false
```

### 2.3 登录与登出

```java
// 用户服务：登录成功后颁发 Token
@PostMapping("/login")
public Result<LoginVO> login(@RequestBody LoginDTO dto) {
    // 1. 验证用户名密码
    User user = userService.verifyCredentials(dto.getUsername(), dto.getPassword());
    
    // 2. Sa-Token 登录，生成 Token 存入 Redis
    StpUtil.login(user.getId());
    
    // 3. 返回 Token 信息
    SaTokenInfo tokenInfo = StpUtil.getTokenInfo();
    LoginVO loginVO = new LoginVO();
    loginVO.setToken(tokenInfo.getTokenValue());
    loginVO.setUserId(user.getId());
    return Result.success(loginVO);
}

// 用户服务：退出登录
@PostMapping("/logout")
public Result<Void> logout(@RequestHeader("X-User-ID") Long userId) {
    // 注销当前 Token
    StpUtil.logout(userId);
    return Result.success();
}
```

## 3. 网关鉴权流程

```mermaid
flowchart TD
    A[接收客户端请求] --> B{路径在白名单？}
    B -->|是| C[直接转发，不注入 X-User-ID]
    B -->|否| D[读取 satoken 请求头]
    D --> E{satoken 存在？}
    E -->|否| F[返回 401 未登录]
    E -->|是| G[查询 Redis: sa_token:{token}]
    G --> H{Redis 中存在 userId？}
    H -->|否| I[返回 401 Token 已过期]
    H -->|是| J[向请求注入 X-User-ID 头]
    J --> K[转发请求至下游服务]
    K --> L[返回响应给客户端]

    style F fill:#ff6b6b,color:#fff
    style I fill:#ff6b6b,color:#fff
    style C fill:#51cf66,color:#fff
    style L fill:#51cf66,color:#fff
```

### 3.1 网关鉴权过滤器实现要点

```java
@Component
public class AuthGlobalFilter implements GlobalFilter, Ordered {
    
    // 白名单路径列表（从 Nacos 配置中读取，支持热更新）
    @Value("${security.whitelist}")
    private List<String> whitelist;
    
    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        String path = exchange.getRequest().getPath().value();
        
        // Step 1: 白名单检查
        if (isWhitelisted(path)) {
            return chain.filter(exchange);
        }
        
        // Step 2: 获取 Token
        String token = exchange.getRequest().getHeaders().getFirst("satoken");
        if (!StringUtils.hasText(token)) {
            return writeUnauthorized(exchange, "请先登录");
        }
        
        // Step 3: 验证 Token（查 Redis）
        return Mono.fromCallable(() -> {
                // 使用 Sa-Token 响应式 API 验证
                return SaReactorHolder.getContext().getLoginIdByToken(token);
            })
            .flatMap(userId -> {
                if (userId == null) {
                    return writeUnauthorized(exchange, "登录已过期，请重新登录");
                }
                // Step 4: 注入 X-User-ID
                ServerWebExchange mutated = exchange.mutate()
                    .request(r -> r.header("X-User-ID", String.valueOf(userId)))
                    .build();
                return chain.filter(mutated);
            });
    }
    
    @Override
    public int getOrder() { return -100; }
}
```

## 4. Token 存储设计

### 4.1 Redis Key 结构

Sa-Token 在 Redis 中的 Key 格式（由框架自动管理）：

| Key 格式 | 对应信息 | TTL |
|----------|----------|-----|
| `satoken:login:token:{token}` | Token → userId 映射 | 7 天 |
| `satoken:login:session:{userId}` | 用户 Session 对象 | 7 天 |
| `satoken:login:last-activity:{token}` | 最后活跃时间戳 | 24 小时 |

### 4.2 Redis 内存估算

| 数据项 | 单条大小 | 并发用户数 | 预估内存 |
|--------|----------|-----------|----------|
| Token 映射 | ~200 Bytes | 1000 | ~200 KB |
| Session 对象 | ~500 Bytes | 1000 | ~500 KB |
| 合计 | — | — | ~1 MB（极少） |

> Redis 的 `maxmemory` 设置为 `96mb`，Token 存储消耗极少，主要用于业务缓存。

## 5. 接口放行白名单设计

### 5.1 白名单接口列表

| 接口路径 | 请求方法 | 说明 |
|----------|----------|------|
| `/api/user/login` | POST | 用户登录 |
| `/api/user/register` | POST | 用户注册 |
| `/actuator/health` | GET | 服务健康检查 |
| `/actuator/info` | GET | 服务信息 |

### 5.2 白名单配置方式

白名单配置存储在 Nacos 的 `gateway.yaml` 中，支持热更新：

```yaml
# gateway.yaml (存储在 Nacos)
security:
  whitelist:
    - /api/user/login
    - /api/user/register
    - /actuator/health
    - /actuator/info
```

### 5.3 白名单匹配策略

- **精确匹配**：`/api/user/login` 只匹配该路径
- **前缀匹配**：`/api/public/**` 匹配所有 `/api/public/` 开头的路径（使用 `AntPathMatcher`）
- **优先级**：白名单判断在鉴权之前执行

## 6. 权限控制扩展（角色与权限）

### 6.1 用户角色设计

| 角色 | 标识 | 权限范围 |
|------|------|----------|
| 普通用户 | `user` | 操作自己的数据 |
| 管理员 | `admin` | 管理所有用户数据 |

### 6.2 权限注解使用

```java
// 仅管理员可访问
@SaCheckRole("admin")
@GetMapping("/admin/users")
public Result<Page<UserVO>> listAllUsers(...) { ... }

// 已登录用户可访问（通过 X-User-ID 头保证）
@GetMapping("/info")
public Result<UserVO> getUserInfo(@RequestHeader("X-User-ID") Long userId) { ... }
```
