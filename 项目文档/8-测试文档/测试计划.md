# 测试计划

> **文档版本**：v1.0.0 | **最后更新**：2026-06-07 | **状态**：规划中

## 1. 测试范围

### 1.1 纳入测试范围

- ✅ 所有微服务的 Service 层业务逻辑
- ✅ 所有对外暴露的 REST API 接口
- ✅ 关键业务流程的集成测试（注册→登录→查询→修改）
- ✅ 数据库 CRUD 操作的正确性
- ✅ 鉴权机制（Token 验证、白名单放行）

### 1.2 暂不纳入测试范围

- ❌ Mapper 层（简单 CRUD，由 MyBatis-Plus 框架保证）
- ❌ 配置类（Bean 定义）
- ❌ VO/DTO/Entity 等 POJO 类（无业务逻辑）
- ❌ 性能极限压测（非毕业设计重点）

## 2. 测试类型

### 2.1 单元测试（Unit Testing）

**目标**：验证单个类/方法的正确性，隔离外部依赖（Mock）。

| 项目 | 说明 |
|------|------|
| 测试框架 | JUnit 5（`org.junit.jupiter`） |
| Mock 框架 | Mockito（`@MockitoBean`、`@Mock`） |
| 覆盖范围 | Service 层核心业务逻辑 |
| 覆盖率目标 | Service 层 ≥ 60% |
| 命名规范 | `{类名}Test.java`，方法名 `test{方法名}_{场景}` |

**示例**：
```java
@ExtendWith(MockitoExtension.class)
class UserServiceImplTest {
    
    @Mock
    private UserMapper userMapper;
    
    @Mock
    private PasswordEncoder passwordEncoder;
    
    @InjectMocks
    private UserServiceImpl userService;
    
    @Test
    void testRegister_WhenUsernameExists_ShouldThrowBusinessException() {
        // Given
        UserRegisterDTO dto = new UserRegisterDTO();
        dto.setUsername("existingUser");
        dto.setPassword("password123");
        
        when(userMapper.existsByUsername("existingUser")).thenReturn(true);
        
        // When & Then
        assertThrows(BusinessException.class, () -> userService.register(dto));
        verify(userMapper, never()).insert(any());
    }
    
    @Test
    void testRegister_WhenValid_ShouldSucceed() {
        // Given
        UserRegisterDTO dto = new UserRegisterDTO();
        dto.setUsername("newUser");
        dto.setPassword("password123");
        
        when(userMapper.existsByUsername("newUser")).thenReturn(false);
        when(passwordEncoder.encode("password123")).thenReturn("$2a$10$...");
        when(userMapper.insert(any())).thenReturn(1);
        
        // When
        Result<?> result = userService.register(dto);
        
        // Then
        assertEquals(200, result.getCode());
        verify(userMapper).insert(any());
    }
}
```

### 2.2 集成测试（Integration Testing）

**目标**：验证多个组件协同工作的正确性（Service + Mapper + 数据库）。

| 项目 | 说明 |
|------|------|
| 测试框架 | Spring Boot Test（`@SpringBootTest`） |
| 数据库 | H2 内存数据库（隔离测试数据）或 Testcontainers |
| 事务回滚 | `@Transactional` 注解确保测试数据不污染 |
| 范围 | Service + Mapper + 真实数据库（内存 H2） |

### 2.3 接口测试（API Testing）

**目标**：验证 HTTP 接口的请求/响应正确性，包含鉴权、参数校验等。

| 项目 | 说明 |
|------|------|
| 工具 | Postman / IntelliJ IDEA HTTP Client |
| 环境 | 本地开发环境或测试服务器 |
| 测试重点 | 正常流程 + 边界条件 + 错误场景 |
| 文档 | 测试用例记录在 [接口测试记录](./接口测试记录.md) |

### 2.4 性能测试（Performance Testing）

**目标**：验证系统在一定负载下的响应时间和吞吐量。

| 项目 | 说明 |
|------|------|
| 工具 | Apache JMeter |
| 测试场景 | 登录接口并发压测（100并发，持续 60s） |
| 目标指标 | P95 响应时间 < 500ms，成功率 > 99% |
| 计划时间 | > 📝 待补充 |
