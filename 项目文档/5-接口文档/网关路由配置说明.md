# 网关路由配置说明

> **文档版本**：v2.0.0 | **最后更新**：2026-08-06 | **状态**：已完成

---

## 1. 概述

本文档说明 Spring Cloud Gateway 的路由配置规范，包括路由规则格式、当前路由列表、跨域配置和鉴权白名单配置。所有路由配置存储在 Nacos 配置中心的 `gateway.yaml` 中，支持热更新。

---

## 2. 路由规则格式

### 2.1 配置文件结构

```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: {路由唯一ID}
          uri: lb://{服务名}          # lb:// 表示负载均衡，通过 Nacos 服务发现
          predicates:
            - Path={路径匹配规则}     # 路径断言
          filters:
            - StripPrefix=1           # 去除路径前缀层数
```

### 2.2 Predicate（断言）说明

| Predicate 类型 | 配置示例 | 说明 |
|---------------|----------|------|
| `Path` | `Path=/api/user/**` | 路径匹配（支持 `**` 通配符） |
| `Method` | `Method=GET,POST` | HTTP 方法匹配 |
| `Header` | `Header=X-Request-Id, \d+` | 请求头匹配（正则） |
| `Query` | `Query=token, .+` | 查询参数匹配 |
| `After` | `After=2025-01-01T00:00:00+08:00` | 在指定时间之后生效 |

### 2.3 Filter（过滤器）说明

| Filter | 配置示例 | 说明 |
|--------|----------|------|
| `StripPrefix` | `StripPrefix=1` | 转发前去除 N 层路径前缀 |
| `AddRequestHeader` | `AddRequestHeader=X-Source, gateway` | 添加请求头 |
| `AddResponseHeader` | `AddResponseHeader=X-Response-Time, 1000` | 添加响应头 |
| `RewritePath` | `RewritePath=/api/user(?<segment>/?.*), $\{segment}` | 路径重写 |
| `CircuitBreaker` | `CircuitBreaker=name=serviceA,fallback...` | 熔断器 |
| `RequestRateLimiter` | `RequestRateLimiter=...` | 限流 |

## 4. 跨域（CORS）配置说明

### 4.1 跨域配置原则

由于所有请求统一经过网关，跨域配置**集中在网关**处理，下游服务**不需要**单独配置 CORS。

### 4.2 当前跨域配置

```yaml
spring:
  cloud:
    gateway:
      globalcors:
        cors-configurations:
          '[/**]':
            # 允许的来源（生产环境应改为具体域名）
            allowed-origins:
              - "http://localhost:3000"
              - "http://localhost:5173"
              - "http://122.51.234.113"
            # 允许的 HTTP 方法
            allowed-methods:
              - GET
              - POST
              - PUT
              - DELETE
              - OPTIONS
            # 允许的请求头
            allowed-headers: "*"
            # 允许携带凭证（Cookie）
            allow-credentials: true
            # 预检请求缓存时间（秒）
            max-age: 3600
            # 暴露给前端的响应头
            exposed-headers:
              - satoken
```

### 4.3 跨域注意事项

1. **`allow-credentials: true`**：允许跨域携带 Cookie，此时 `allowed-origins` **不能使用 `*`**，必须明确指定域名
2. **`OPTIONS` 方法**：必须包含，浏览器在实际请求前会发送 OPTIONS 预检请求
3. **生产环境**：`allowed-origins` 必须限制为具体的前端域名，不得使用通配符

## 5. 鉴权白名单配置

### 5.1 白名单配置位置

白名单路径存储在 Nacos 的 `gateway.yaml` 中，支持动态更新（需配合 `@RefreshScope`）：

```yaml
# gateway.yaml (Nacos)
security:
  # 不需要鉴权的路径白名单
  whitelist:
    - /api/user/login
    - /api/user/register
    - /api/memorial/deceased/list
    - /actuator/health
    - /actuator/info
    - /favicon.ico
```

### 5.2 白名单匹配逻辑

```java
// 白名单匹配（支持精确匹配和 Ant 路径模式）
private boolean isWhitelisted(String path) {
    AntPathMatcher matcher = new AntPathMatcher();
    return whitelist.stream()
        .anyMatch(pattern -> matcher.match(pattern, path));
}
```

### 5.3 白名单设计原则

1. **最小化白名单**：只放行真正不需要鉴权的接口，避免安全漏洞
2. **明确路径**：尽量使用精确路径，避免过于宽泛的通配符（如 `/api/**`）
3. **定期审查**：在每次新增接口时，审查白名单是否需要更新

## 6. 全局过滤器执行顺序

网关中的 Filter 按 `getOrder()` 返回值从小到大依次执行（数值越小优先级越高）：

| Filter 名称 | Order 值 | 说明 |
|-------------|---------|------|
| `AuthGlobalFilter`（鉴权） | -100 | 最先执行，拦截无效请求 |
| `LogGlobalFilter`（日志） | -50 | 记录请求日志 |
| Spring Cloud Gateway 内置 Filter | 0~N | 路由、负载均衡等 |

## 7. 新路由接入规范

当新微服务需要通过网关对外暴露时，按以下步骤操作：

1. **在 Nacos 中更新 `gateway.yaml`**，添加路由规则
2. **配置路径规范**：路径格式为 `/api/{服务简称}/**`（如 `/api/file/**`）
3. **更新本文档**：在路由列表中添加新路由的记录
4. **更新白名单**：如有不需鉴权的接口，添加到白名单
5. **测试验证**：验证路由转发是否正常，鉴权是否按预期工作
