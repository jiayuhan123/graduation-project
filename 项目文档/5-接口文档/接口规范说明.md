# 接口规范说明

## 1. 基本约定

- 外部 API 统一使用 `/api/{service}/...` 路径并经过 Gateway。
- 请求和响应使用 UTF-8 编码的 JSON。
- 查询使用 `GET`，新增使用 `POST`，整体修改使用 `PUT`，局部修改使用 `PATCH`，删除使用 `DELETE`。
- 时间字段使用 ISO 8601 格式，明确时区；数据库内部统一约定时区。
- 主键可能超过 JavaScript 安全整数范围，前端应按字符串处理长整型 ID。

## 2. 统一响应

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

业务失败仍返回相同结构，`code` 使用项目错误码。HTTP 状态码用于表达协议层结果，业务码用于表达具体原因，两者不应互相替代。

## 3. 鉴权请求

登录成功后，客户端使用响应中的 `tokenName` 作为请求头名称并携带 Token。外部客户端不得设置 `X-User-ID`、`X-User-Role` 等内部身份头，这些字段由网关重建。

## 4. 参数与分页

分页查询推荐参数：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `page` | Integer | 1 | 页码，从 1 开始 |
| `size` | Integer | 10 | 每页数量，应设置上限 |
| `orderBy` | String | 由接口定义 | 只允许后端白名单字段 |
| `orderDir` | String | `desc` | `asc` 或 `desc` |

服务端必须校验 DTO，不直接把外部字段拼接到 SQL、排序表达式或文件路径。

## 5. 已分配错误码

| 范围 | 模块 |
|---:|---|
| 1000—1999 | 用户服务 |
| 2000—2999 | 文件服务 |
| 3000 以上 | 新业务服务按段分配 |

具体错误码以 `ResultCode` 和《异常处理规范》为准。

## 6. 幂等与安全

- 创建订单、提交审批等重要写操作应设计幂等键或唯一约束。
- 文件上传校验大小、扩展名、MIME 类型和访问权限。
- 日志脱敏手机号、证件号、Token、密码和密钥。
- 接口变更应同步更新文档、前端调用和自动化测试。
