## 1. 项目背景

祭扫是中华民族传承孝道、缅怀先人的重要传统活动。然而，传统祭扫方式存在**焚烧纸钱、燃放鞭炮**等不文明行为，既污染环境又存在火灾隐患；同时，**清明等集中祭扫时段**人员聚集、秩序混乱，给社区管理带来巨大压力。

随着数字化社区治理的推进，各地社区积极探索"文明祭扫"新模式。本课题面向**特定社区**（小区、街道、村居等基层单元），设计并实现一套线上线下结合的**文明祭扫系统**：

- **线上祭扫**：居民可在线为逝者建立纪念档案，通过献花、点烛、留言等方式寄托哀思，减少实地聚集；
- **祭扫预约**：对线下祭扫实施**错峰预约**管理，合理控制各时段祭扫人数，保障祭扫秩序与安全；
- **宣传引导**：社区通过公告栏发布文明祭扫倡议、政策法规，引导居民践行绿色祭扫新风尚。

在技术上，本项目以**微服务架构设计与实践**为核心命题，基于 Spring Cloud 生态构建完整的微服务后端系统，覆盖服务注册与发现、统一鉴权、配置中心、消息异步解耦、对象存储等企业级微服务核心能力，作为毕业设计的工程实践载体。

---

## 2. 项目目标

### 2.1 业务目标

1. **线上祭扫服务**：实现逝者纪念档案的创建、审核、展示与线上祭扫（献花/点烛/上香/留言），让居民足不出户寄托哀思；
2. **错峰预约管理**：实现线下祭扫的分时段预约、确认与统计，缓解集中祭扫压力；
3. **文明祭扫宣传**：通过社区公告与站内通知，推送文明祭扫倡议与政策信息；
4. **社区治理支撑**：为社区管理员提供档案审核、预约管理、祭扫统计等管理能力。

### 2.2 技术目标

1. **构建微服务基础架构**：实现基于 Spring Cloud 的完整微服务基础设施，包括注册中心、配置中心、API 网关等核心组件；
2. **实现统一鉴权体系**：基于 Sa-Token + Redis 在网关层实现统一鉴权，下游服务通过请求头安全获取用户身份；
3. **实践异步解耦通信**：通过 RabbitMQ 实现服务间异步消息通信（如注册欢迎、祭扫提醒、审核通知），提升系统吞吐量与容错能力；
4. **实现容器化部署**：使用 Docker Compose 实现中间件的容器化编排，降低部署复杂度；
5. **输出完整文档体系**：建立符合工程规范的项目文档，涵盖架构设计、接口规范、部署指南等。

### 2.3 学术目标

- 深入理解微服务架构的设计原则与权衡取舍（Trade-off）
- 掌握 Spring Cloud Alibaba 生态的核心组件使用
- 实践 DevOps 理念中的容器化部署流程
- 具备完整的系统设计与文档撰写能力

## 3. 系统功能模块概览

### 3.1 已实现模块

| 模块 | 服务名 | 端口 | 功能描述 | 状态 |
|------|--------|------|----------|------|
| API 网关 | `gateway` | 10000 | 请求路由、统一鉴权、跨域处理 | ✅ 已完成 |
| 用户与社区服务 | `user-service` | 8001 | 居民注册、登录、社区绑定、个人信息管理 | 🔄 开发中 |

### 3.2 规划中模块

| 模块 | 服务名 | 功能描述 | 计划状态 |
|------|--------|----------|----------|
| 纪念祭扫服务 | `memorial-service` | 逝者纪念档案管理、线上祭扫（献花/点烛/留言）、祭扫错峰预约 | 📋 待开发 |
| 文件服务 | `file-service` | 逝者照片、祭扫图片等文件上传/下载，基于 MinIO 对象存储 | 📋 待开发 |
| 通知服务 | `notify-service` | 祭扫提醒、社区公告、站内信通知，消费 RabbitMQ 消息 | 📋 待开发 |
| 管理后台 | `management` | 社区管理员审核档案、管理预约、发布公告、数据统计 | 📋 待开发 |

### 3.3 用户角色设计

| 角色 | 标识 | 权限范围 |
|------|------|----------|
| 居民 | `resident` | 创建/管理自己家属的逝者档案、线上祭扫、预约祭扫、查看公告 |
| 社区管理员 | `community_admin` | 审核逝者档案、确认/取消预约、发布公告、查看祭扫统计 |
| 系统管理员 | `admin` | 社区管理、用户管理、全局配置 |
