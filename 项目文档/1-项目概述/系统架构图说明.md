## 2. 请求处理流程图

```mermaid
sequenceDiagram
    participant C as 客户端
    participant G as Gateway (10000)
    participant R as Redis
    participant S as 业务服务

    C->>G: HTTP 请求（携带 satoken 头）
    
    alt 白名单接口（/login, /register）
        G->>S: 直接转发
        S->>C: 响应结果
    else 需要鉴权的接口
        G->>R: 查询 Token 对应的 UserId
        alt Token 有效
            R-->>G: 返回 UserId
            G->>S: 转发请求（注入 X-User-ID 请求头）
            S->>C: 响应结果
        else Token 无效/过期
            G->>C: 返回 401 Unauthorized
        end
    end
```

## 3. 各层职责说明

### 3.1 客户端层

| 客户端类型 | 说明 |
|------------|------|
| 浏览器 | Web 前端应用，通过 HTTP/HTTPS 访问 API |
| 移动端 App | iOS/Android 应用（若有），通过 HTTP/HTTPS 访问 API |

所有客户端统一通过 **API Gateway（端口 10000）** 作为唯一入口，不直接访问后端业务服务。

### 3.2 网关层（Gateway）

**职责**：
- **统一入口**：所有外部请求必须经过网关，内部服务之间通过 Feign 直接调用
- **身份鉴权**：解析请求头中的 `satoken`，通过 Redis 验证 Token 有效性，提取 `userId` 注入 `X-User-ID` 请求头
- **路由转发**：根据路由规则将请求转发到对应的后端服务（通过 Nacos 服务发现）
- **跨域处理**：统一配置跨域（CORS）策略，下游服务无需单独处理
- **全局过滤**：请求日志记录、限流（可扩展）等全局处理

**技术实现**：`spring-cloud-starter-gateway-server-webflux`（WebFlux 响应式）

### 3.3 业务服务层

| 服务 | 端口 | 主要职责 |
|------|------|----------|
| `user-service` | 8001 | 用户注册、登录（颁发Token）、用户信息CRUD、密码修改 |
| `file-service` | 待定 | 文件上传至 MinIO、生成访问 URL、文件管理 |
| `notify-service` | 待定 | 消费 RabbitMQ 消息，发送邮件/站内信通知 |

**服务间通信方式**：
- **同步调用**：OpenFeign（基于 HTTP，走 Nacos 服务发现 + 负载均衡）
- **异步通信**：RabbitMQ（业务事件发布，通知服务订阅消费）

### 3.4 注册与配置中心（Nacos）

| 功能 | 说明 |
|------|------|
| 服务注册 | 各微服务启动时向 Nacos 注册实例，心跳保活 |
| 服务发现 | 网关和 Feign 通过 Nacos 查询目标服务的实例列表 |
| 配置管理 | 各服务配置集中存储于 Nacos，DataID 格式：`${spring.application.name}.yaml` |
| 配置热更新 | 配置变更后，Nacos 自动推送至各服务，无需重启 |

### 3.5 数据存储层

| 组件 | 端口 | 用途 |
|------|------|------|
| MySQL 8.4 | 3306 | 用户信息、业务数据等持久化存储 |
| Redis 8.0 | 6379 | Sa-Token Token 存储、热点数据缓存、分布式锁 |
| MinIO | 9000(API)/9001(Web) | 用户头像、附件等二进制文件存储 |

### 3.6 消息中间件（RabbitMQ）

| 场景 | 生产者 | 消费者 | 说明 |
|------|--------|--------|------|
| 用户注册通知 | `user-service` | `notify-service` | 用户注册成功后发送欢迎邮件 |
| 异步日志记录 | 各业务服务 | 日志消费者（待规划） | 操作日志异步入库 |

```
互联网
   │
   ▼

   │
   ▼
防火墙（开放端口：10000/8001/...）
   │
   ▼
Docker 网络（bridge 模式）
   ├── gateway:10000
   ├── user-service:8001
   ├── mysql:3306
   ├── redis:6379
   ├── nacos:8848/8847/9848
   ├── rabbitmq:5672/15672
   └── minio:9000/9001
```

> **安全建议**：生产环境中，中间件端口（MySQL/Redis/RabbitMQ 等）不应直接对外暴露，应仅允许 Docker 内部网络访问。仅网关端口（10000）和必要的管理端口对外开放。
