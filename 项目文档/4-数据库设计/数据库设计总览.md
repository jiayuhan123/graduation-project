# 数据库设计总览

> **文档版本**：v1.0.0 | **最后更新**：2026-06-07 | **状态**：已完成

---

## 1. 数据库设计原则

### 1.1 总体原则

1. **微服务数据库隔离**：每个微服务独立使用自己的数据库 Schema，严禁跨服务直接操作数据库
2. **最小数据原则**：每个服务只存储本服务业务所需的数据
3. **逻辑删除优先**：业务数据不物理删除，使用 `deleted` 字段标记删除状态
4. **统一字符集**：所有数据库、表、字段统一使用 `utf8mb4` 字符集，排序规则 `utf8mb4_unicode_ci`
5. **时区统一**：数据库服务器时区设置为 `Asia/Shanghai`（UTC+8），所有时间字段存储北京时间

### 1.2 存储引擎

所有业务表统一使用 **InnoDB** 存储引擎，理由：
- 支持事务（ACID）
- 支持行级锁，并发性能好
- 支持外键约束（本项目暂不使用，但引擎支持）

## 2. 命名规范

### 2.1 数据库名命名

```
格式：{服务名}_db
示例：
  - user_db    → 用户服务数据库
  - file_db    → 文件服务数据库
  - notify_db  → 通知服务数据库
```

### 2.2 表名命名

```
格式：t_{业务模块名}
规则：全小写，单词间用下划线分隔
示例：
  - t_user      → 用户表
  - t_file      → 文件表
  - t_message   → 消息表
```

### 2.3 字段命名

| 规则 | 示例 |
|------|------|
| 全小写，单词间用下划线 | `create_time`、`user_name` |
| 布尔/状态字段用 tinyint | `status`（0/1）、`deleted`（0/1） |
| 外键字段加 `_id` 后缀 | `user_id`、`file_id` |
| 时间字段加 `_time` 后缀 | `create_time`、`update_time` |

### 2.4 索引命名

| 索引类型 | 命名格式 | 示例 |
|----------|----------|------|
| 主键 | `PRIMARY` | — |
| 唯一索引 | `uk_{字段名}` | `uk_username` |
| 普通索引 | `idx_{字段名}` | `idx_create_time` |
| 联合索引 | `idx_{字段1}_{字段2}` | `idx_status_create_time` |

## 3. 公共字段规范

所有业务表**必须**包含以下公共字段：

| 字段名 | 类型 | 是否可空 | 说明 |
|--------|------|----------|------|
| `id` | BIGINT UNSIGNED | NOT NULL | 主键，自增 |
| `create_time` | DATETIME | NOT NULL | 创建时间，DEFAULT CURRENT_TIMESTAMP |
| `update_time` | DATETIME | NOT NULL | 更新时间，DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP |
| `deleted` | TINYINT(1) | NOT NULL | 逻辑删除标记，0-未删除，1-已删除，DEFAULT 0 |

**MyBatis-Plus 自动填充配置**：
- `create_time`：INSERT 时自动填充（`@TableField(fill = FieldFill.INSERT)`）
- `update_time`：INSERT 和 UPDATE 时自动填充（`@TableField(fill = FieldFill.INSERT_UPDATE)`）
- `deleted`：配合 `@TableLogic` 注解实现透明逻辑删除

## 4. 数据库实例分配

### 4.1 当前数据库实例

本项目使用单一 MySQL 实例（`122.51.234.113:3306`），通过不同 Schema 隔离各服务数据：

| Schema 名 | 所属服务 | 状态 | 说明 |
|-----------|----------|------|------|
| `user_db` | user-service | 🔄 创建中 | 用户相关数据 |
| `file_db` | file-service | 📋 待创建 | 文件元数据 |
| `notify_db` | notify-service | 📋 待创建 | 通知消息数据 |

### 4.2 数据库创建 SQL

```sql
-- 创建用户服务数据库
CREATE DATABASE IF NOT EXISTS user_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

-- 创建文件服务数据库
CREATE DATABASE IF NOT EXISTS file_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;

-- 创建通知服务数据库
CREATE DATABASE IF NOT EXISTS notify_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
```

## 6. MySQL 连接配置模板

```yaml
# 各服务 Nacos 配置中的 MySQL 配置段（示例：user-service.yaml）
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://122.51.234.113:3306/user_db?useUnicode=true&characterEncoding=utf8mb4&serverTimezone=Asia/Shanghai&useSSL=false
    username: root
    password: 111111  # 生产环境请使用更强密码
    hikari:
      maximum-pool-size: 10
      minimum-idle: 5
      connection-timeout: 30000
      idle-timeout: 600000
      max-lifetime: 1800000
```

> 📝 待补充：考虑引入 Flyway 或 Liquibase 进行数据库版本管理，实现 SQL 脚本的版本控制和自动迁移。

| 工具 | 说明 | 建议 |
|------|------|------|
| Flyway | 版本化 SQL 脚本，文件格式 `V{version}__{description}.sql` | **推荐** |
