# 公共服务数据库设计

## 1. 数据库隔离

| 数据库 | 所属服务 | 主要表 |
| --- | --- | --- |
| `user_db` | User Service | `sys_outbox_event`（另见用户/RBAC文档） |
| `file_db` | File Service | `file_object` |
| `notification_db` | Notification Service | `notification` |
| `audit_db` | Audit Service | `audit_log` |

各服务使用自己的连接与 Flyway 历史，不建立跨库外键。

## 2. 事务发件箱

`sys_outbox_event` 以 UUID `id` 作为事件 ID，保存事件类型、路由键、JSON 载荷、状态、重试次数、下次重试时间、发布时间和最后错误。状态仅允许 `PENDING`、`PUBLISHED`、`FAILED`；部分索引只覆盖待发布数据。

## 3. 文件元数据

`file_object` 保存所有者、原始安全文件名、唯一 OSS 对象键、MIME、字节数、SHA-256、创建时间和逻辑删除标记。二进制内容不进入 PostgreSQL。查询同时约束 `id` 与 `owner_id`，避免越权枚举。

## 4. 通知

`notification` 保存接收用户、类型、标题、正文、已读状态、已读时间和来源事件 ID。`source_event_id` 唯一保证消费幂等；用户/时间和未读部分索引支持常用查询。

## 5. 审计

`audit_log` 保存事件 ID、操作者、来源服务、动作、目标和发生时间。`event_id` 唯一保证消费幂等。`detail` 禁止写入密码、Token、AccessKey、完整手机号等敏感信息。

## 6. 初始化与迁移

根目录 `deploy/postgres/init/01-create-service-databases.sql` 仅在 PostgreSQL 数据目录首次初始化时创建数据库。之后由每个服务的 `V1__...sql` 创建表。已执行迁移不得编辑，结构变化追加 `V2__...sql` 等新版本。
