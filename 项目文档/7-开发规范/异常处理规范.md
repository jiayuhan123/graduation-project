# 异常处理规范

> **文档版本**：v2.0.0 | **最后更新**：2026-08-06 | **状态**：已完成

---

## 1. 概述

本文档定义了项目中异常处理的统一规范，包括：
- 全局异常处理器的设计
- 自定义业务异常类的定义
- 错误码枚举的规范
- 异常处理最佳实践

统一的异常处理机制确保所有接口在异常情况下都能返回格式一致、信息清晰的错误响应。

```

 （业务异常）        （参数校验异常）              （系统异常）
```

## 3. 错误码枚举（ResultCode）

### 3.1 错误码枚举定义

```java
package xyz.jiayuhan.common.result;

import lombok.AllArgsConstructor;
import lombok.Getter;

/**
 * 统一业务错误码枚举
 * <p>
 * 错误码规范：
 * - 200：操作成功
 * - 4xx：客户端错误（参数、权限、资源等）
 * - 5xx：服务器端错误
 * - 1xxx：用户与社区模块业务错误（10xx 居民账号、11xx 社区、12xx 纪念档案、13xx 祭扫预约）
 * - 2xxx：文件模块业务错误
 * </p>
 */
@Getter
@AllArgsConstructor
public enum ResultCode {

    // =================== 通用成功 ===================
    SUCCESS(200, "操作成功"),

    // =================== 通用错误 ===================
    BAD_REQUEST(400, "请求参数错误"),
    UNAUTHORIZED(401, "未登录，请先登录"),
    FORBIDDEN(403, "无权限访问"),
    NOT_FOUND(404, "资源不存在"),
    CONFLICT(409, "数据冲突"),
    TOO_MANY_REQUESTS(429, "请求过于频繁，请稍后再试"),
    INTERNAL_SERVER_ERROR(500, "服务器内部错误"),
    SERVICE_UNAVAILABLE(503, "服务暂不可用"),

    // =================== 居民账号（10xx） ===================
    USERNAME_OR_PASSWORD_ERROR(1001, "用户名或密码错误"),
    USERNAME_EXISTS(1002, "用户名已存在"),
    PHONE_EXISTS(1003, "手机号已被注册"),
    USER_DISABLED(1004, "账号已被禁用，请联系管理员"),
    OLD_PASSWORD_ERROR(1005, "旧密码不正确"),

    // =================== 社区（11xx） ===================
    COMMUNITY_NOT_FOUND(1101, "社区不存在或已停用"),
    ALREADY_JOINED_COMMUNITY(1102, "居民已加入该社区"),
    NOT_COMMUNITY_MEMBER(1103, "不属于该社区成员"),

    // =================== 纪念档案（12xx） ===================
    DECEASED_NOT_FOUND(1201, "纪念档案不存在"),
    DECEASED_STATUS_NOT_ALLOWED(1202, "纪念档案状态不允许操作"),
    DECEASED_NO_PERMISSION(1203, "无权限操作该档案"),
    SENSITIVE_WORD_FOUND(1204, "内容含敏感词"),

    // =================== 祭扫预约（13xx） ===================
    SLOT_IS_FULL(1301, "预约时段已满额"),
    APPOINTMENT_EXISTS(1302, "该时段已存在预约"),
    APPOINTMENT_STATUS_NOT_ALLOWED(1303, "预约状态不允许该操作"),
    APPOINTMENT_TIME_PASSED(1304, "预约时间已过，无法取消"),

    // =================== 文件模块（2xxx） ===================
    FILE_NOT_FOUND(2000, "文件不存在"),
    FILE_UPLOAD_FAILED(2001, "文件上传失败"),
    FILE_SIZE_EXCEEDED(2002, "文件大小超出限制"),
    FILE_TYPE_NOT_ALLOWED(2003, "文件类型不允许"),

    // =================== 扩展预留 ===================
    ;

    /**
     * 业务状态码
     */
    private final Integer code;

    /**
     * 描述信息
     */
    private final String message;
}
```

## 4. 自定义业务异常类

```java
package xyz.jiayuhan.common.exception;

import lombok.Getter;
import xyz.jiayuhan.common.result.ResultCode;

/**
 * 业务异常类
 * <p>
 * 用于在业务逻辑层抛出预期内的业务错误（如用户名已存在、密码错误等）。
 * 与 RuntimeException 区别：BusinessException 是"已知"的业务异常，
 * RuntimeException 是"未知"的系统异常。
 * </p>
 *
 * <p>使用示例：</p>
 * <pre>
 *     if (userExists) {
 *         throw new BusinessException(ResultCode.USERNAME_EXISTS);
 *     }
 * </pre>
 */
@Getter
public class BusinessException extends RuntimeException {

    /**
     * 业务错误码
     */
    private final Integer code;

    /**
     * 错误描述
     */
    private final String message;

    /**
     * 通过 ResultCode 枚举构造
     *
     * @param resultCode 错误码枚举
     */
    public BusinessException(ResultCode resultCode) {
        super(resultCode.getMessage());
        this.code = resultCode.getCode();
        this.message = resultCode.getMessage();
    }

    /**
     * 通过 ResultCode 枚举 + 自定义消息构造
     *
     * @param resultCode 错误码枚举（使用其 code）
     * @param message    自定义错误描述
     */
    public BusinessException(ResultCode resultCode, String message) {
        super(message);
        this.code = resultCode.getCode();
        this.message = message;
    }

    /**
     * 通过自定义错误码和消息构造
     *
     * @param code    错误码
     * @param message 错误描述
     */
    public BusinessException(Integer code, String message) {
        super(message);
        this.code = code;
        this.message = message;
    }
}
```

## 5. 全局异常处理器

### 5.1 业务服务全局异常处理器（Servlet 环境）

```java
package xyz.jiayuhan.user.handler;

import jakarta.validation.ConstraintViolation;
import jakarta.validation.ConstraintViolationException;
import lombok.extern.slf4j.Slf4j;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import xyz.jiayuhan.common.exception.BusinessException;
import xyz.jiayuhan.common.result.Result;
import xyz.jiayuhan.common.result.ResultCode;

import java.util.stream.Collectors;

/**
 * 全局异常处理器
 * <p>
 * 捕获所有 Controller 抛出的未处理异常，转换为统一的 Result 响应格式。
 * </p>
 */
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    /**
     * 处理业务异常（已知的业务逻辑错误）
     */
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        log.warn("业务异常: code={}, message={}", e.getCode(), e.getMessage());
        return Result.fail(e.getCode(), e.getMessage());
    }

    /**
     * 处理请求体参数校验失败（@Valid + @RequestBody）
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        // 收集所有字段的错误信息
        String errorMessage = e.getBindingResult().getFieldErrors()
            .stream()
            .map(FieldError::getDefaultMessage)
            .collect(Collectors.joining("; "));
        
        log.warn("参数校验失败: {}", errorMessage);
        return Result.fail(ResultCode.BAD_REQUEST.getCode(), errorMessage);
    }

    /**
     * 处理路径参数/查询参数校验失败（@Validated + @PathVariable/@RequestParam）
     */
    @ExceptionHandler(ConstraintViolationException.class)
    public Result<Void> handleConstraintViolationException(ConstraintViolationException e) {
        String errorMessage = e.getConstraintViolations()
            .stream()
            .map(ConstraintViolation::getMessage)
            .collect(Collectors.joining("; "));
        
        log.warn("约束校验失败: {}", errorMessage);
        return Result.fail(ResultCode.BAD_REQUEST.getCode(), errorMessage);
    }

    /**
     * 处理所有其他未预期的异常（系统异常）
     */
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        // 系统异常必须打印完整堆栈，便于排查
        log.error("系统异常，请检查日志排查原因", e);
        return Result.fail(ResultCode.INTERNAL_SERVER_ERROR);
    }
}
```

### 5.2 网关全局异常处理器（WebFlux 响应式环境）

```java
package xyz.jiayuhan.gateway.handler;

import com.fasterxml.jackson.core.JsonProcessingException;
import com.fasterxml.jackson.databind.ObjectMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.boot.web.reactive.error.ErrorWebExceptionHandler;
import org.springframework.core.annotation.Order;
import org.springframework.core.io.buffer.DataBufferFactory;
import org.springframework.http.MediaType;
import org.springframework.stereotype.Component;
import org.springframework.web.server.ResponseStatusException;
import org.springframework.web.server.ServerWebExchange;
import reactor.core.publisher.Mono;
import xyz.jiayuhan.common.result.Result;
import xyz.jiayuhan.common.result.ResultCode;

/**
 * 网关全局异常处理器（WebFlux 响应式）
 */
@Slf4j
@Order(-1)
@Component
@RequiredArgsConstructor
public class GatewayGlobalExceptionHandler implements ErrorWebExceptionHandler {

    private final ObjectMapper objectMapper;

    @Override
    public Mono<Void> handle(ServerWebExchange exchange, Throwable ex) {
        Result<Void> result;
        
        if (ex instanceof BusinessException businessException) {
            result = Result.fail(businessException.getCode(), businessException.getMessage());
        } else if (ex instanceof ResponseStatusException responseStatusException) {
            result = Result.fail(responseStatusException.getStatusCode().value(), 
                                  responseStatusException.getReason());
        } else {
            log.error("网关未知异常", ex);
            result = Result.fail(ResultCode.INTERNAL_SERVER_ERROR);
        }

        return writeResponse(exchange, result);
    }
    
    private Mono<Void> writeResponse(ServerWebExchange exchange, Result<Void> result) {
        exchange.getResponse().getHeaders().setContentType(MediaType.APPLICATION_JSON);
        DataBufferFactory bufferFactory = exchange.getResponse().bufferFactory();
        try {
            byte[] bytes = objectMapper.writeValueAsBytes(result);
            return exchange.getResponse().writeWith(
                Mono.just(bufferFactory.wrap(bytes))
            );
        } catch (JsonProcessingException e) {
            return Mono.error(e);
        }
    }
}
```

## 6. 异常处理最佳实践

### 6.1 应该做的（✅ DO）

```java
// ✅ 业务异常用 BusinessException
if (!user.getStatus().equals(1)) {
    throw new BusinessException(ResultCode.USER_DISABLED);
}

// ✅ 系统异常记录完整日志
try {
    // 调用外部服务
} catch (Exception e) {
    log.error("调用外部服务失败，参数：userId={}", userId, e); // 第三个参数传异常对象
    throw new BusinessException(ResultCode.SERVICE_UNAVAILABLE);
}

// ✅ 参数校验使用 @Valid 注解，配合 JSR-303 注解
@PostMapping("/register")
public Result<?> register(@Valid @RequestBody UserRegisterDTO dto) { ... }
```

### 6.2 不应该做的（❌ DON'T）

```java
// ❌ 不要在 Controller 中 try-catch 业务异常，交给全局处理器处理
@PostMapping("/register")
public Result<?> register(@RequestBody UserRegisterDTO dto) {
    try {
        return userService.register(dto);
    } catch (BusinessException e) {
        return Result.fail(e.getCode(), e.getMessage()); // 重复了全局处理器的工作
    }
}

// ❌ 不要直接返回 null 或空字符串作为错误信息
throw new BusinessException(1002, null);  // message 为 null，前端无法显示

// ❌ 不要吞掉异常（空 catch 块）
try {
    // ...
} catch (Exception e) {
    // 什么都不做！错误被吞掉，极难排查
}

// ❌ 不要在 catch 后再 throw new RuntimeException(e)，会丢失原始异常类型
// 应该直接 throw 原始异常，或 throw 明确类型的业务异常
```
