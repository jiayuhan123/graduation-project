# 异常处理规范

## 1. 基本原则

- 控制器返回统一的 `Result<T>`，不直接拼装无固定结构的响应。
- 可预期的业务失败抛出 `BusinessException` 并关联 `ResultCode`。
- 参数校验使用 Jakarta Validation，由全局异常处理器统一转换。
- 系统异常记录完整日志，对客户端只返回安全、简洁的信息。
- 不在日志或响应中输出密码、Token、密钥等敏感数据。

## 2. 错误码分段

| 范围 | 用途 |
|---:|---|
| 200 | 操作成功 |
| 400—499 | 请求、认证、权限或资源错误 |
| 500—599 | 服务端或依赖服务错误 |
| 1000—1999 | 用户模块业务错误 |
| 2000—2999 | 文件模块业务错误 |
| 3000 以上 | 新业务按服务分段申请，避免冲突 |
