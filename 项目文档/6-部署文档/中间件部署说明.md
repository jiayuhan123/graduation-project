# 中间件部署说明

## 1. 唯一配置来源

根目录 [`docker-compose.yaml`](../../docker-compose.yaml) 是当前本地中间件编排的唯一配置来源。文档不复制整份 YAML，避免两份配置漂移。

当前服务：

| Compose 服务 | 镜像 | 主要用途 |
|---|---|---|
| `postgres` | `postgres:18` | 用户与后续业务数据 |
| `redis` | `redis:8.0` | Sa-Token 会话和短期状态 |
| `nacos` | `nacos/nacos-server:v3.2.2` | 注册发现与配置 |
| `rabbitmq` | `rabbitmq:management` | 后续业务异步消息 |
| `jenkins` | `jenkins/jenkins:lts` | CI/CD |

当前未编排 MinIO。确需对象存储时应先按新选题确定访问控制、Bucket 和备份策略，再修改 Compose 与文档。

## 2. 启动

在项目根目录执行：

```powershell
# 校验 YAML
docker compose config --quiet

# 用户服务最小依赖
docker compose up -d postgres redis nacos

# 启动全部中间件
docker compose up -d

# 查看状态
docker compose ps
```

Docker Desktop 用户需要先启动 Docker Desktop。`docker compose config` 不需要运行中的 Docker daemon，但 `up` 需要。

## 3. 本地连接信息

| 组件 | 地址 | 本地开发凭据 |
|---|---|---|
| PostgreSQL | `localhost:5432/user_db` | `root / 111111` |
| Redis | `localhost:6379` | 密码 `111111`，DB 0 |
| Nacos API | `localhost:8848` | 由 Compose 鉴权配置决定 |
| Nacos 控制台 | `http://localhost:8847` | 仅本地访问 |
| RabbitMQ AMQP | `localhost:5672` | `root / 111111` |
| RabbitMQ 控制台 | `http://localhost:15672` | `root / 111111` |
| Jenkins | `http://localhost:8080` | 首次启动后创建 |

这些值仅用于本地开发。部署到共享或生产环境前必须更换全部密码，并避免开放数据库、Redis、Nacos API 和 AMQP 端口。

## 4. 数据持久化

Compose 把数据写入根目录 `data/`：

```text
data/
├── postgres/
├── redis/
├── nacos/
├── rabbitmq/
└── jenkins/
```

该目录不应提交 Git。升级镜像、迁移服务器或清理容器前先备份。不要通过删除 `data/` 解决普通启动错误，这会造成不可恢复的数据丢失。

## 5. 用户数据库初始化

PostgreSQL 容器通过 `POSTGRES_DB=user_db` 创建空库。`user-service` 首次启动后，Flyway 自动执行：

```text
back/user-service/src/main/resources/db/migration/
└── V1__create_user_and_rbac_schema.sql
```

验证：

```powershell
docker exec -it micro-postgres psql -U root -d user_db -c "\dt"
```

应看到 `t_user`、`sys_role`、`sys_permission`、`sys_user_role`、`sys_role_permission` 和 `flyway_schema_history`。

## 6. 常用运维命令

```powershell
docker compose logs -f postgres redis nacos
docker compose restart nacos
docker compose pull
docker compose up -d
docker compose stop
```

`docker compose down` 会删除容器和网络，但默认保留绑定目录中的数据；执行任何带卷删除或手工删除 `data/` 的操作前必须确认备份和目标路径。

## 7. 健康排查

| 现象 | 检查 |
|---|---|
| User Service 数据源失败 | `docker compose ps postgres`、`DB_URL`、账号密码 |
| Token 写入失败 | Redis 状态、`REDIS_*`、Gateway 与用户服务 DB 编号 |
| Nacos 注册失败 | 8848/9848 端口、`NACOS_SERVER_ADDR`、容器日志 |
| Flyway 失败 | 数据库权限、`flyway_schema_history`、迁移校验信息 |
| Jenkins OOM | Compose 内存限制、宿主机内存和 `MAVEN_OPTS` |

## 8. 生产原则

- 使用专用数据库账号并按最小权限授权；
- Redis 绑定内网，配置强密码、持久化和备份；
- Nacos 开启认证并限制控制台访问；
- 在 Gateway 前部署 HTTPS 反向代理；
- 配置容器健康检查、日志轮转、监控和告警；
- 数据库迁移前备份，迁移文件只追加不修改；
- 镜像版本应固定，禁止在生产使用未经验证的浮动标签。
