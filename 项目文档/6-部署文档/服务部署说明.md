# 服务部署说明

> **文档版本**：v1.0.0 | **最后更新**：2026-06-07 | **状态**：部分完成（随开发进度持续更新）

---

## 1. 概述

本文档说明微服务应用的打包、配置、部署与健康检查流程。当前阶段中间件已通过 Docker Compose 部署完成，本文重点描述 Java 微服务的部署流程。

---

## 2. 前提条件

在部署微服务之前，确保以下条件已满足：

- [x] 服务器上 Docker Compose 已启动所有中间件（MySQL、Redis、Nacos、RabbitMQ、MinIO）
- [x] Nacos 中已配置各服务的配置文件（DataID 格式：`${spring.application.name}.yaml`）
- [x] MySQL 中已创建对应的数据库 Schema 和数据表
- [ ] 服务器上已安装 JDK 21
- [ ] 防火墙已开放网关端口（10000）

---

## 3. Nacos 配置准备

### 3.1 各服务配置文件说明

在部署前，需先在 Nacos 控制台（`http://122.51.234.113:8847/nacos`）中创建以下配置：

| DataID | Group | 所属服务 | 说明 |
|--------|-------|----------|------|
| `gateway.yaml` | DEFAULT_GROUP | gateway | 网关路由、白名单、跨域配置 |
| `user-service.yaml` | DEFAULT_GROUP | user-service | 用户服务全量配置 |

### 3.2 gateway.yaml 配置模板

```yaml
server:
  port: 10000

spring:
  application:
    name: gateway
  cloud:
    gateway:
      routes:
        - id: user-service
          uri: lb://user-service
          predicates:
            - Path=/api/user/**

      globalcors:
        cors-configurations:
          '[/**]':
            allowed-origins:
              - "http://localhost:3000"
              - "http://localhost:5173"
            allowed-methods: ["GET", "POST", "PUT", "DELETE", "OPTIONS"]
            allowed-headers: "*"
            allow-credentials: true
            max-age: 3600

# 鉴权白名单
security:
  whitelist:
    - /api/user/login
    - /api/user/register
    - /actuator/health

# Sa-Token Redis 配置
sa-token:
  token-name: satoken
  timeout: 604800
  active-timeout: 86400
```

### 3.3 user-service.yaml 配置模板

```yaml
server:
  port: 8001

spring:
  application:
    name: user-service
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://mysql:3306/user_db?useUnicode=true&characterEncoding=utf8mb4&serverTimezone=Asia/Shanghai&useSSL=false
    username: root
    password: 111111
    hikari:
      maximum-pool-size: 10
      minimum-idle: 5

  data:
    redis:
      host: redis
      port: 6379
      password: 111111
      database: 0

  rabbitmq:
    host: rabbitmq
    port: 5672
    username: root
    password: 111111
    virtual-host: /

# MyBatis-Plus
mybatis-plus:
  mapper-locations: classpath*:mapper/**/*.xml
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0

# Sa-Token
sa-token:
  token-name: satoken
  timeout: 604800
  active-timeout: 86400
  is-concurrent: true
  is-share: false
  token-style: uuid
```

> **注意**：配置文件中 `host` 使用 Docker 容器名（如 `mysql`、`redis`），而非 IP 地址。这依赖于各服务运行在同一 Docker 网络中或能通过域名解析到中间件地址。若微服务以 JAR 包形式在服务器上直接运行（非 Docker），则应使用 `127.0.0.1` 或服务器内网 IP。

## 4. 微服务打包

### 4.1 打包命令

```bash
# 在项目根目录执行（父工程）
mvn clean package -DskipTests

# 或打包指定模块
mvn clean package -pl gateway -DskipTests
mvn clean package -pl user-service -DskipTests
```

### 4.2 打包产物位置

```
graduation-project/
├── gateway/
│   └── target/
│       └── gateway-1.0.0-SNAPSHOT.jar    ← 打包产物
├── user-service/
│   └── target/
│       └── user-service-1.0.0-SNAPSHOT.jar
```

### 4.3 将 JAR 上传到服务器

```bash
# 使用 SCP 上传到服务器
scp gateway/target/gateway-1.0.0-SNAPSHOT.jar root@122.51.234.113:/opt/services/gateway/
scp user-service/target/user-service-1.0.0-SNAPSHOT.jar root@122.51.234.113:/opt/services/user-service/
```

服务器目录结构建议：
```
/opt/services/
├── gateway/
│   ├── gateway-1.0.0-SNAPSHOT.jar
│   └── start.sh
├── user-service/
│   ├── user-service-1.0.0-SNAPSHOT.jar
│   └── start.sh
└── logs/
    ├── gateway/
    └── user-service/
```

## 5. 服务启动

### 5.1 启动命令

```bash
# 启动网关服务
java -Xms128m -Xmx192m \
  -Dspring.profiles.active=prod \
  -Dspring.cloud.nacos.server-addr=127.0.0.1:8848 \
  -jar /opt/services/gateway/gateway-1.0.0-SNAPSHOT.jar \
  > /opt/services/logs/gateway/gateway.log 2>&1 &

# 启动用户服务
java -Xms192m -Xmx256m \
  -Dspring.profiles.active=prod \
  -Dspring.cloud.nacos.server-addr=127.0.0.1:8848 \
  -jar /opt/services/user-service/user-service-1.0.0-SNAPSHOT.jar \
  > /opt/services/logs/user-service/user-service.log 2>&1 &
```

### 5.2 启动脚本（start.sh）

```bash
#!/bin/bash
# /opt/services/gateway/start.sh

APP_NAME="gateway"
JAR_FILE="/opt/services/gateway/gateway-1.0.0-SNAPSHOT.jar"
LOG_FILE="/opt/services/logs/gateway/gateway.log"
NACOS_ADDR="127.0.0.1:8848"

# 检查是否已在运行
PID=$(pgrep -f "$JAR_FILE")
if [ -n "$PID" ]; then
    echo "$APP_NAME is already running (PID: $PID)"
    exit 1
fi

# 启动服务
nohup java -Xms128m -Xmx192m \
    -Dspring.profiles.active=prod \
    -Dspring.cloud.nacos.server-addr=$NACOS_ADDR \
    -jar $JAR_FILE \
    > $LOG_FILE 2>&1 &

echo "$APP_NAME started, PID: $!, log: $LOG_FILE"
```

### 5.3 停止服务

```bash
# 查找并停止指定服务
pkill -f "gateway-1.0.0-SNAPSHOT.jar"
pkill -f "user-service-1.0.0-SNAPSHOT.jar"
```

### 5.4 服务启动顺序

```
1. 启动 Docker Compose 中间件（Nacos、MySQL、Redis、RabbitMQ、MinIO）
2. 等待 Nacos 完全启动（约 30-60 秒）
3. 启动业务服务（user-service 等）
4. 启动网关服务（gateway）—— 最后启动，确保下游服务已注册
```

## 6. 健康检查

### 6.1 Actuator 端点

所有微服务应配置 Spring Boot Actuator 并暴露健康检查端点：

```yaml
# 在各服务的配置文件中添加
management:
  endpoints:
    web:
      exposure:
        include: health,info
  endpoint:
    health:
      show-details: always
```

**健康检查 URL**：

| 服务 | 健康检查 URL | 直接访问 | 网关访问 |
|------|------------|----------|----------|
| gateway | `http://122.51.234.113:10000/actuator/health` | — | — |
| user-service | `http://122.51.234.113:8001/actuator/health` | 直接访问 | — |

**正常响应示例**：
```json
{
    "status": "UP",
    "components": {
        "db": { "status": "UP" },
        "redis": { "status": "UP" },
        "diskSpace": { "status": "UP" }
    }
}
```

### 6.2 Nacos 服务注册验证

启动微服务后，在 Nacos 控制台（服务管理 → 服务列表）验证服务是否已注册：

```
期望看到：
✅ gateway          实例数: 1
✅ user-service     实例数: 1
```

### 6.3 接口冒烟测试

```bash
# 测试登录接口（白名单，不需要 Token）
curl -X POST http://122.51.234.113:10000/api/user/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}'

# 期望返回：{"code":200,"message":"登录成功","data":{"token":"..."}}
```

## 7. 服务更新流程（热更新）

```bash
# 1. 打包新版本
mvn clean package -pl user-service -DskipTests

# 2. 上传新 JAR
scp user-service/target/user-service-*.jar root@122.51.234.113:/opt/services/user-service/

# 3. 停止旧服务
pkill -f "user-service"

# 4. 等待 Nacos 摘除旧实例（约 15 秒）
sleep 15

# 5. 启动新服务
/opt/services/user-service/start.sh

# 6. 验证健康状态
curl http://122.51.234.113:8001/actuator/health
```
