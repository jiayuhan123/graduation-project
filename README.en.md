# Personalized Primary Math Practice and Game Challenge Platform

This project is a learning platform for primary-school arithmetic. Version 1 focuses on three core capabilities: photo-assisted grading, personalized arithmetic practice, and individual/team game challenges. All answers generated by these entry points feed one learning loop:

```text
Practice, photo submission, or game challenge
    -> trusted grading
    -> error diagnosis
    -> mastery update
    -> targeted practice
    -> re-verification
```

## Version 1 scope

- Photo-assisted grading for supported, structurally clear arithmetic question types.
- Personalized practice based on grade, selected knowledge points, recent mistakes, error types, speed, mastery, and time since the last practice.
- Individual challenges with a default of 10 questions, a total time limit, and an 80% pass threshold. All three values are configurable challenge attributes.
- Team challenges for 2-4 students with equivalent questions, shared progress, and individual contribution records.
- Teacher assignments, low-confidence review, student/class reports, content management, and rule management.

The developer open platform is paused. Real-time one-to-one PK is an optional later extension and is not a Version 1 completion requirement.

## Content model

Version 1 uses the compact structure `content module -> knowledge point -> question`. Grade, semester, publisher, edition notes, question count, time limit, and pass threshold are modeled as attributes instead of unnecessary standalone entities. The conceptual ER diagram presents student, teacher, and administrator as business entities, while the implementation still uses a shared-account RBAC model. A textbook-chapter mapping can be added later if real textbook alignment is required.

## Current codebase

- Java 21 / Spring Boot 4 modular monolith in `back`.
- `monolith-app` is the only runnable backend and exposes all APIs on port `10000`.
- User, content, learning, teaching, game, file, notification, and audit boundaries remain separate Maven modules in one JVM and one PostgreSQL database.
- Redis, RabbitMQ, transactional outboxes, and the future extraction contracts remain available; the active runtime does not depend on Gateway, Nacos, or service discovery.
- Vue 3 management frontend foundation.
- The student experience is planned as a WeChat mini program.
